## Figma file structure (observed 29 Oct 2026)

The file has been renamed to **ChronoMap 3D Prototype** (it previously said "Low-Fi", which
would have been a poor first impression on a high-fidelity deliverable).

Three pages:

| Page | Contents |
| --- | --- |
| **Page 1 · Hi Fi** | The high-fidelity prototype (v1). This is the submission. |
| Page 2 · Low fi | The A2 wireframes. Keep - they are the iteration evidence. |
| Page 3 · Editorial | Presentation/editorial frames. |

Page 1 is organised into six labelled sections:

- **A · Onboarding & discovery**
- **B · Community, reporting & moderation**
- **C · Rally & briefing**
- **D · Capture & voice call**
- **E · Artifact & sharing**
- **F · Profile**

It also carries a published text-style set (Display, H1, H2, Title, Body, BodySm, Label, Caption,
Btn, Num) and a `ChronoMap` style group - worth mentioning in the report's visual-design section,
since a named type ramp is evidence of a system rather than ad-hoc screens.

### Version lineage

Sketches → storyboard → low-fidelity wireframes (A2) → **high-fidelity v1 (current, and what gets
evaluated)** → **high-fidelity v2 (built after usability testing, submitted with the report)**.

The handout requires that v2 exist: *"Make improvements to your high-fidelity prototype based on
lessons learned from this evaluation."*
